# DualSense 控制器协议参考

技术参考文档，提取自 [daidr/dualsense-tester](https://github.com/daidr/dualsense-tester)。涵盖 DualSense、DualSense Edge 和 DualShock 4（v1/v2）。

## 1. 设备识别

| 设备 | Vendor ID | Product ID |
|------|-----------|------------|
| 所有索尼手柄 | `0x054C` | — |
| DualShock 4 v1 | `0x054C` | `0x05C4` |
| DualShock 4 v2 | `0x054C` | `0x09CC` |
| DualSense | `0x054C` | `0x0CE6` |
| DualSense Edge | `0x054C` | `0x0DF2` |

HID usage page: `0x0001`（通用桌面），usage: `0x0005`（游戏手柄）。

### 连接类型检测

DualSense 通过检查 HID 描述符来区分 USB 和蓝牙连接：

- **USB**：最大输入报告字节数 = **504 bits**（63 字节）
- **蓝牙**：最大输入报告字节数 = **616 bits**（77 字节）

DualShock 4 使用相同的 504 位阈值判断 USB；其他情况默认为蓝牙。

| `0x80` | Feature | Feature | 发送工厂/测试命令 |
| `0x81` | Feature | Feature | 接收工厂/测试结果 |
| `0x84` | Feature | Feature | 单项数据校验启动 |
| `0x85` | Feature | Feature | 单项数据校验结果 |

## 3. 输入报告结构（DualSense）

输入报告是手柄发出的主要数据流。USB 和蓝牙的偏移量相差一个字节，因为蓝牙在前面附加了一个 report ID 字节。

### 字节布局

| 偏移（USB） | 偏移（BT） | 大小 | 字段 | 说明 |
|------------|-----------|------|------|------|
| 0 | 1 | 1 | `analogStickLX` | 左摇杆 X 轴（0-255，中心=128） |
| 1 | 2 | 1 | `analogStickLY` | 左摇杆 Y 轴（0-255，中心=128） |
| 2 | 3 | 1 | `analogStickRX` | 右摇杆 X 轴（0-255，中心=128） |
| 3 | 4 | 1 | `analogStickRY` | 右摇杆 Y 轴（0-255，中心=128） |
| 4 | 5 | 1 | `analogTriggerL` | 左扳机模拟值（0-255） |
| 5 | 6 | 1 | `analogTriggerR` | 右扳机模拟值（0-255） |
| 6 | 7 | 1 | `sequenceNum` | 序列号（0-255，循环） |
| 7 | 8 | 3 | `digitalKeys` | 十字键 + 按键（见下文） |
| 10 | 11 | 1 | — | 保留 |
| 11 | 12 | 4 | `incrementalNumber` | 递增计数器 |
| 15 | 16 | 2 | `gyroPitch` | 陀螺仪俯仰角（int16 LE，有符号） |
| 17 | 18 | 2 | `gyroYaw` | 陀螺仪偏航角（int16 LE，有符号） |
| 19 | 20 | 2 | `gyroRoll` | 陀螺仪翻滚角（int16 LE，有符号） |
| 21 | 22 | 2 | `accelX` | 加速度计 X 轴（int16 LE，有符号） |
| 23 | 24 | 2 | `accelY` | 加速度计 Y 轴（int16 LE，有符号） |
| 25 | 26 | 2 | `accelZ` | 加速度计 Z 轴（int16 LE，有符号） |
| 27 | 28 | 4 | `motionTimeStamp` | 运动时间戳（uint32 LE） |
| 31 | 32 | 1 | `motionTemperature` | 运动传感器温度 |
| 32 | 33 | 9 | `touchData` | 触摸板数据（见下文） |
| 41 | 42 | 1 | `atStatus0` | 自适应扳机状态 0 |
| 42 | 43 | 1 | `atStatus1` | 自适应扳机状态 1 |
| 43 | 44 | 4 | `hostTimestamp` | 主机时间戳（uint32 LE） |
| 47 | 48 | 1 | `atStatus2` | 自适应扳机状态 2 |
| 48 | 49 | 1 | `activeProfile` | 当前配置文件（仅 Edge） |
| 49 | 50 | 1 | `triggerLevel` | 扳机级别（仅 Edge） |
| 52 | 53 | 1 | `status0` | 电池/充电状态 |
| 53 | 54 | 1 | `status1` | 耳机/麦克风检测 |
| 54 | 55 | 1 | `status2` | 状态字节 2 |
| 55 | 56 | 16 | `aesCmac` | AES-CMAC 认证标签 |
| — | 73 | 4 | `crc32` | CRC32 校验和（仅 BT） |

### DualSense Edge 差异

- 字节 48（USB）/ 49（BT）：`activeProfile` — 低 2 位 = 0 表示正常模式，否则为配置文件配置模式
- 字节 49（USB）/ 50（BT）：`triggerLevel`
- 蓝牙的 `sequenceNum` 位于偏移 0（不是偏移 1）

## 5. 模拟摇杆归一化

原始值为 0-255 无符号整数。归一化到 `[-1.0, +1.0]`：

```
normalized = (2 * raw) / 255 - 1.0
```

中心值（128）映射到约 `0.0`。

## 6. 触摸板数据

触摸板数据占据 9 个字节，起始于偏移 32（USB）/ 33（BT）。支持两个触点，分辨率为 **1920 x 1080**。

### 触点 1（touchData 的字节 0-3）

| 字节 | 位 | 字段 |
|------|------|------|
| 0 | 7-0 | 触摸 ID（位 7 = 接触标志；ID = value & 0x7F） |
| 1 | 7-0 | X 低 8 位 |
| 2 | 3-0 | X 高 4 位 |
| 2 | 7-4 | Y 低 4 位 |
| 3 | 7-0 | Y 高 8 位 |

**重建公式：**
```
id   = touchData[0] & 0x7F
x    = ((touchData[2] & 0x0F) << 8) | touchData[1]
y    = (touchData[3] << 4) | (touchData[2] >> 4)
```

X 范围：0-1920，Y 范围：0-1080。

触摸 ID < 128 表示有效触摸；触摸 ID 用于跨帧跟踪单个手指。

### 触点 2（touchData 的字节 4-7）

编码方式与触点 1 相同，起始于字节 4：
```
id   = touchData[4] & 0x7F
x    = ((touchData[6] & 0x0F) << 8) | touchData[5]
y    = (touchData[7] << 4) | (touchData[6] >> 4)
```

### 物理尺寸

- 触摸板实际宽度：430 px
- 触摸板实际高度：235 px
- 触摸板在手柄绘图上的偏移：(340, 160)

## 7. 陀螺仪和加速度计

| 字段 | 偏移（USB） | 偏移（BT） | 类型 |
|------|------------|-----------|------|
| `gyroPitch` | 15 | 16 | int16 LE |
| `gyroYaw` | 17 | 18 | int16 LE |
| `gyroRoll` | 19 | 20 | int16 LE |
| `accelX` | 21 | 22 | int16 LE |
| `accelY` | 23 | 24 | int16 LE |
| `accelZ` | 25 | 26 | int16 LE |
| `motionTimeStamp` | 27 | 28 | uint32 LE |

运动时间戳提供积分角速度的时间基准。温度字段表示 IMU 传感器温度。

## 9. 输出报告结构（DualSense）

输出报告发送到手柄以控制震动、LED、自适应扳机和触觉反馈。46 字节载荷（USB report ID `0x02`，BT report ID `0x31`）。

### 字节布局

| 偏移 | 字段 | 默认值 | 说明 |
|------|------|--------|------|
| 0 | `validFlag0` | `0x00` | 位掩码：哪些字段生效（见下文） |
| 1 | `validFlag1` | `0xF7` | 第二组字段的位掩码 |
| 2 | `bcVibrationRight` | `0x00` | 右马达震动强度（0-255） |
| 3 | `bcVibrationLeft` | `0x00` | 左马达震动强度（0-255） |
| 4 | `headphoneVolume` | `0x00` | 耳机音量 |
| 5 | `speakerVolume` | `0x00` | 扬声器音量 |
| 6 | `micVolume` | `0x00` | 麦克风音量 |
| 7 | `audioControl` | `0x00` | 音频控制标志 |
| 8 | `muteLedControl` | `0x00` | 静音 LED 控制 |
| 9 | `powerSaveMuteControl` | `0x00` | 省电/静音控制 |
| 10 | `adaptiveTriggerRightMode` | `0x00` | 右扳机效果模式 |
| 11-20 | `adaptiveTriggerRightParam0-9` | `0x00` | 右扳机效果参数 |
| 21 | `adaptiveTriggerLeftMode` | `0x00` | 左扳机效果模式 |
| 22-31 | `adaptiveTriggerLeftParam0-9` | `0x00` | 左扳机效果参数 |
| 32-35 | 保留 | — | 保留字节 |
| 36 | `hapticVolume` | `0x00` | 触觉反馈音量 |
| 37 | `audioControl2` | `0x00` | 附加音频控制 |
| 38 | `validFlag2` | `0x00` | 第三个有效标志字节 |
| 39 | 保留 | — | |
| 40 | `lightbarSetup` | `0x00` | 灯条设置 |
| 41 | `ledBrightness` | `0x00` | LED 亮度 |
| 42 | `playerIndicator` | `0x00` | 玩家 LED 位掩码 |
| 43 | `ledCRed` | `0x00` | 灯条红色（0-255） |
| 44 | `ledCGreen` | `0xFF` | 灯条绿色（0-255） |
| 45 | `ledCBlue` | `0x00` | 灯条蓝色（0-255） |

### validFlag0 位掩码

有效标志控制手柄实际应用输出报告的哪些部分：

| 位 | 字段 |
|----|------|
| 5 | 扬声器音量 |
| 7 | 音频控制 / 耳机音量 |

### validFlag1 位掩码

| 位 | 字段 |
|----|------|
| 1 | 静音 LED |
| 3 | 玩家指示灯 |
| 4 | 灯条颜色 |
| 5 | 省电模式 |

默认值 `0xF7` 启用除震动和扳机效果外的大部分字段。

### 蓝牙输出报告包装

蓝牙模式下，输出报告载荷被包装如下：

```
字节 0: (seq << 4) | 0x00     // 高半字节为序列号
字节 1: 0x10                    // 固定标志字节
字节 2-77: 原始载荷             // 46 字节输出结构 + 填充
字节 74-77: CRC32               // 对 [0xA2, 0x31] + 字节 0-73 计算
```

总计：78 字节。CRC32 对前缀 `[0xA2, 0x31]` 拼接报告数据的字节 0 至 73 进行计算。

## 10. 自适应扳机效果

每个扳机（左/右）在输出报告中有一个模式字节 + 10 个参数字节。

### 效果模式

| 模式 | 名称 | 参数 | 说明 |
|------|------|------|------|
| `0x00` | 关闭 | （无） | 无效果 |
| `0x01` | 阻力 | `start_pos`, `force` | 从指定位置开始的恒定阻力 |
| `0x02` | 软扳机 | `start_pos`, `end_pos`, `force` | 两个位置之间的震动区域 |
| `0x06` | 自动扳机 | `start_pos`, `force`, `frequency` | 在指定位置和频率自动震动 |

### 参数详情

**模式 0x01 — 阻力：**
- `Param0`（字节 0）：`start_pos`（0-255，映射到物理扳机位置）
- `Param1`（字节 1）：`force`（0-255，阻力强度）

**模式 0x02 — 软扳机：**
- `Param0`（字节 0）：`start_pos`（0-255）
- `Param1`（字节 1）：`end_pos`（0-255）
- `Param2`（字节 2）：`force`（0-255）

**模式 0x06 — 自动扳机：**
- `Param0`（字节 0）：`frequency`（0-15）
- `Param1`（字节 1）：`force`（0-255）
- `Param2`（字节 2）：`start_pos`（0-255）

剩余参数字节（3-9）为保留/零值。

## 12. 蓝牙音频流（Report 0x36）

蓝牙音频使用 report ID `0x36`，397 字节载荷 + 4 字节 CRC32。报告包含三个子包：控制、音频（Opus）和触觉反馈（PCM）。

### 报告布局（397 字节）

| 偏移 | 大小 | 字段 |
|------|------|------|
| 0 | 1 | 序列号（高半字节）+ 标志（低半字节，恒为 0） |
| 1-65 | 65 | 控制子包 |
| 66-276 | 211 | 音频子包（Opus） |
| 277-392 | 116 | 触觉子包（PCM） |
| 393-396 | 4 | CRC32（前缀 `[0xA2, 0x36]`） |

### 控制子包（65 字节，偏移 1）

| 偏移 | 字段 |
|------|------|
| 0 | `0x90` 标记 |
| 1 | 有效标志 |
| 6 | 音量 / 音频目标 |
| 10 | `audioControl`（0x09） |

### 音频子包（211 字节，偏移 66）

| 偏移 | 字段 |
|------|------|
| 0 | `0x91` 标记 |
| 1 | `0x07` |
| 2-7 | 延迟/混音参数 |
| 8 | 帧计数器（递增） |
| 9 | 输出路由标签：`0x93` = 扬声器，`0x96` = 耳机 |
| 10 | `0xC8`（= 200，Opus 帧长度） |
| 11-210 | 200 字节 Opus 编码音频 |

### 触觉子包（116 字节，偏移 277）

| 偏移 | 字段 |
|------|------|
| 0 | `0x92` 标记 |
| 1 | `0x40`（= 64，PCM 块长度） |
| 2-65 | 64 字节：32 样本 x 2 声道（L/R 交织，int8） |

### Opus 编码参数

| 参数 | 值 |
|------|-----|
| 采样率 | 48000 Hz（标称；实际约 45000 Hz） |
| 声道数 | 2（立体声） |
| 比特率 | 160 kbps CBR |
| 帧时长 | 10 ms |
| 应用类型 | `lowdelay`（纯 CELT） |
| 帧大小 | 200 字节（固定） |

### 触觉音频提取

音频被重采样到 **3000 Hz** 用于触觉处理，然后转换为有符号 8 位整数：

```
int8_value = clamp(round(sample * 127), -128, 127) & 0xFF
```

每个触觉帧 = 每声道 32 个样本，L/R 交织：`[L0, R0, L1, R1, ..., L31, R31]` = 64 字节。

## 13. 蓝牙麦克风协议

### 输入报告（Report ID 0x31）

第一个字节的低半字节决定载荷类型：

| 载荷类型 | 值 | 说明 |
|---------|-----|------|
| 控制 | `0x01` | 麦克风状态和控制 |
| 音频 | `0x02` | Opus 编码的麦克风音频 |

**控制载荷：**
- 字节 10，位 2：静音按钮按下
- 字节 54，位 1：耳机麦克风已插入

**音频载荷：**
- 字节 2-72：71 字节 Opus 帧

### 输出报告

**麦克风状态报告（report ID `0x31`，77 字节）：**
控制麦克风音量、静音 LED 和音频路由。

| 偏移 | 字段 |
|------|------|
| 0 | `(seq << 4)` |
| 1 | `0x10` |
| 2 | `0xC0` — 麦克风音量 + 音频控制 |
| 3 | `0x83` — 静音 LED + 省电 + 音频控制 2 |
| 8 | 激活且未静音时为 `0x08`，否则 `0x00` |
| 9 | 耳机麦克风插入时为 `0x08`，否则 `0x09` |
| 10 | 静音时为 `0x01`，否则 `0x00` |
| 11 | 激活且未静音时为 `0x0F`，否则 `0x1F` |
| 39 | `0x01` |
| 73-76 | CRC32 |

**麦克风控制报告（report ID `0x32`，141 字节）：**
打开或关闭 Opus 麦克风流。

| 偏移 | 字段 |
|------|------|
| 0 | `(seq << 4)` |
| 1 | `0x91` |
| 2 | `0x07` |
| 3 | `0xFF`（激活）/ `0xFE`（未激活） |
| 4-8 | `0x40` 填充 |
| 9 | 序列号低半字节 |
| 10 | `0x92` |
| 11 | `0x40` |
| 137-140 | CRC32 |

## 14. CRC32 校验和

### 多项式

标准 CRC32，多项式 `0xEDB88320`（反射位序）。

### 计算

初始值：`0xFFFFFFFF`。最终异或：`0xFFFFFFFF`（即 `crc ^ -1`）。

### 输出报告校验和（蓝牙）

前缀字节：`[0xA2, report_id]`。CRC 对前缀 + 除最后 4 字节（CRC 本身）外的所有报告数据字节进行计算。

### Feature 报告校验和（蓝牙）

前缀字节：`[0x53, report_id]`。算法相同。

### DualShock 4 Feature 报告校验和

前缀字节：`[0xA3, report_id]`。

### DualSense Edge 配置文件校验和

CRC 对从 3 个配置文件报告缓冲区（各 58 字节，去除头部）组装的 170 字节进行计算。写入第三个缓冲区的最后 4 个字节。

## 15. Feature 报告命令（工厂/测试）

工厂命令通过 feature 报告 `0x80` 发送，结果通过 `0x81` 读取。

### 命令格式

**发送（feature 报告 `0x80`）：**
| 字节 | 字段 |
|------|------|
| 0 | 设备 ID（`DualSenseTestDeviceId`） |
| 1 | 操作 ID（`DualSenseTestActionId`） |
| 2+ | 可选参数 |

**接收（feature 报告 `0x81`）：**
| 字节 | 字段 |
|------|------|
| 0 | Report ID（`0x81`） |
| 1 | 设备 ID（回显） |
| 2 | 操作 ID（回显） |
| 3 | 状态（0=空闲, 1=运行中, 2=完成, 3=完成2, 255=超时） |
| 4-59 | 结果数据（每页 56 字节） |

| 1 | SYSTEM（系统） |

| 19 | POSITION_TRACKING（位置追踪） |

### 常用命令

| 设备 | 操作 | 名称 | 结果大小 |

| SYSTEM (1) | READ_PCBAID (4) | 读取 PCBA ID | 6 字节 |

## 16. DualSense Edge 配置文件协议

### 配置文件按钮映射

| 按钮 | ID |
|------|-----|
| 方块（Square） | `0x60` |
| 叉（Cross） | `0x61` |
| 圆圈（Circle） | `0x62` |
| 三角（Triangle） | `0x63` |

### 按钮重映射枚举

上、左、下、右、圆圈、叉、方块、三角、R1、R2、R3、L1、L2、L3、左背键、右背键、Options、触摸板。

### 配置文件数据

配置文件通过 3 个 64 字节的 feature 报告缓冲区进行读写。配置文件数据包括：

- **摇杆灵敏度曲线**：7 种预设（DEFAULT、QUICK、PRECISE、STEADY、DIGITAL、DYNAMIC、CUSTOM），支持点数组和死区
- **扳机死区**：每个扳机的最小/最大值（0-255 映射到 0-100%）
- **震动强度**：关闭、弱、中、强
- **扳机效果强度**：关闭、弱、中、强
- **禁用按钮位图**：缓冲区 2 偏移 26-29 的 32 位字段；出厂默认禁用两个背键（`0x00C00000`）

### 配置文件序列化

配置文件可以导出/导入为 JSON，包含 Base64 编码的原始 DataView 对象。

## 17. DualShock 4 差异

### 输入报告偏移

DualShock 4 使用不同的基础偏移：
- USB：基础偏移 +0
- 蓝牙：基础偏移 +2

| 偏移（USB） | 偏移（BT） | 字段 |
|------------|-----------|------|
| 0 | 2 | `analogStickLX` |
| 4 | 6 | `digitalKeys`（3 字节） |
| 6 | 8 | `sequenceNum` |
| 7 | 9 | `analogTriggerL` |
| 9 | 11 | `motionTimeStamp` |
| 12 | 14 | `gyroPitch`（int16 LE） |
| 18 | 20 | `accelX`（int16 LE） |
| 29 | 31 | `status` |
| 34 | 36 | `touchData` |
| — | 73 | `crc32`（仅 BT） |

### 输出报告（Report ID `0x05` USB / `0x11` BT）

73 字节载荷：

| 偏移 | 字段 | 默认值 |
|------|------|--------|
| 0 | `hwControl` | `0xC4` |
| 1 | `audioControl` | — |
| 2-3 | `validFlag0`, `validFlag1` | — |
| 4 | 保留 | — |
| 5 | `motorRight` | 右震动（0-255） |
| 6 | `motorLeft` | 左震动（0-255） |
| 7 | `ledRed` | LED 红色 |
| 8 | `ledGreen` | LED 绿色 |
| 9 | `ledBlue` | LED 蓝色 |
| 10-11 | `ledBlinkOn`, `ledBlinkOff` | LED 闪烁开/关持续时间 |

## 18. 遥测数据

遥测通过设备 `0x70`（TELEMETRY）、操作 `0x01`（GET_INFO）读取，为 56 字节的分页块。

### 通用字段（第 0 页）

- 序列号
- 总记录数
- 活跃时间、充电时间
- 触觉设备时间、扳机设备时间
- 电池充电次数
- USB 检测次数
- 蓝牙连接次数
- 认证次数

### DualSense 标准版（4 页）

额外：摇杆往返次数、所有 20 个按钮的按下次数。

### DualSense Edge（6 页）

额外：扳机行程次数（L2/R2 的短/中/长行程）、背键次数、每个摇杆模块序列号、独立的摇杆往返/按钮/功能按钮次数。

## 19. 音频输出控制

### 工厂波形输出

音频输出可通过工厂测试命令控制：

- **耳机**：使用参数 `[1, 0, 0, 0, 4, 0, 6, ...]` 启用
- **扬声器**：使用参数 `[1, 0, 0, 0, 0, 0, 8, ...]` 启用

### USB 音频路由

USB 音频使用手柄内置声卡：
- 声道 0-1：扬声器输出
- 声道 2-3：触觉马达输出（左/右）
